# V2 设计基础与共享组件

## 做了什么

给医药国际业务个人站铺好了 V2 的底层：统一暖象牙纸张色、棕黑正文、陶土橙和钴蓝强调，整理字体与元数据排版，接入 Phosphor 图标，并重做了页头、页尾、页面 hero、按钮、章节标题、联系条和微信弹窗。英文与中文的菜单、联系渠道和辅助文案也进入同一套类型明确的数据模型。

## 为什么做

旧站虽然功能完整，但视觉还是偏深色企业站，和已批准的编辑式参考图不一致。首页重构会同时依赖很多共享部件，如果不先把颜色、字体、图标和交互接口定稳，后面每个模块都会重复造轮子，也更容易让中英文和可访问性出现分叉。

## 值得记住的决策、坑或技术点

- 图标选了 Phosphor，并用 `ProjectIcon` 再包一层。以后新增图标要同时更新组件联合类型与 Astro 配置白名单，这样不会不知不觉把整套图标打进产物。
- `astro check` 通过不代表运行时一定可用：第一次浏览器检查抓到了 `astro-icon` integration 遗漏导致的 500。补上 integration 后才真正验证了页面，这次再次说明真实浏览器冒烟不能省。
- 微信 dialog 用浏览器原生 `<dialog>` 保留了焦点圈定和 Escape 行为，额外处理触发器回焦与遮罩关闭；移动菜单也同步维护 aria-label、expanded 状态、body 滚动锁和 Escape 回焦。
- 首页只接入共享按钮和图标，没有越界做 Task 2 的模块重排；这让后续首页实现有稳定接口，同时避免两个任务互相踩改动。
- Task 2 的图片在 `public/images/` 里以未跟踪文件出现，这次始终没有暂存或提交它们。

## 一句话亮点

把一个深色企业站的底盘，换成了有纸张温度、编辑感秩序和完整双语交互的医药国际业务设计系统。
