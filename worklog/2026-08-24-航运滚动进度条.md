# 航运滚动进度条

## 1. 做了什么

把第一版放在页头、类似图标的小船方案整体推翻，改成了固定在视口底部的立体集装箱货轮。货轮使用第 1 个已确认的侧视素材，会随整页滚动进度从左向右航行。用户滚动时，船体会产生轻微的上下起伏和左右摇摆；停止滚动后，船体会自然停稳。船尾的白色浪花使用两层错峰循环，在船后持续扩散和淡出。货轮本身同时是可拖拽的页面导航器，横向拖动时页面会跟随定位到对应进度。

## 2. 为什么做

第一版的线性轮船图标太像普通 UI 插件，没有容器船的重量感，方向和浪花也无法让人联想到真正的国际海运。放在页头还会和导航争夺注意力。新方案要让这个细节更像一个克制的品牌彩蛋：有真实的货轮质感和航行节奏，但不抢正文内容。

## 3. 值得记住的决策、坑或技术点

- 最终选择底部横向航线，避免页头过于拥挤，也符合侧视货轮的水平运动方向。
- 生成图最初带有烘焙进去的棋盘格，不能直接当作透明背景使用；后续单独做了背景抽离，成品是真正带 Alpha 通道的 PNG。
- 单独生成的浪花素材多次仍带假棋盘格，因此没有使用。最终从选中货轮本身的真实船尾浪花区域取样，两层以 1.35 秒周期错峰扩散，不会复制出船体残影。
- 船体摇晃只在实际滚动期间启动，使用约 0.95 秒的缓和循环；停止滚动 560 毫秒后取消摇摃，避免页面静止时仍然过度吸睛。
- 货轮与页面总可滚动距离同步，通过动画帧合并高频滚动更新；英文页和中文页共用同一套逻辑，无障碍进度值也会同步更新。
- 拖拽使用 Pointer Events 和指针捕获，鼠标、触控笔和手指共用一套逻辑。按下时会保留实际抓住船体的位置，不会让船在拖拽开始时突然跳到鼠标中心。
- 拖拽初版虽然每次 Pointer Move 都调用了滚动，但全站的 `scroll-behavior: smooth` 会让 `behavior: auto` 继承平滑滚动，导致页面始终落后于指针；滚动回调又会用落后的 `scrollY` 覆盖货轮位置。修复时在拖拽期间改用滚动根元素的同步 `scrollTop`，并暂停这层回写，才是真正的实时跟随。
- 货轮按无障碍横向滑块处理，除了拖动，键盘方向键、Page Up / Page Down、Home 和 End 也能控制页面进度。
- 在系统开启“减少动效”时，船体摇摃和循环尾浪都会停止，只保留静态航程位置。
- 正式素材保存在 `public/images/shipping/cargo-ship-3d-side.png`。

## 4. 一句话亮点

把整页浏览变成一段正在发生的国际航程：立体货轮载着项目轻微摇晃前行，船尾浪花一路延伸。
